# 串口读写阻塞问题分析与修复

## 问题现象

驱动程序在**调试窗口关闭**时，串口写入出现明显延迟（600~800ms），UDP 命令丢帧率约 4%。而**调试窗口打开**时，写入延迟几乎为零，丢帧率为 0%。

两者使用完全相同的代码路径，唯一区别是调试窗口是否可见。

## 根因分析

### 直接原因：Windows 非重叠串口 I/O 在内核层面序列化读写操作

串口以非重叠模式（non-overlapped）打开：

```cpp
// 修复前 — 缺少 FILE_FLAG_OVERLAPPED
m_hPort = CreateFileW(fullPath,
    GENERIC_READ | GENERIC_WRITE, 0, NULL,
    OPEN_EXISTING, 0, NULL);   // ← 同步模式
```

在非重叠模式下，**同一串口句柄的 ReadFile 和 WriteFile 共享一把内核内部锁**。即使分别在不同线程中调用，当一个线程在 ReadFile 中等待数据时，另一个线程的 WriteFile 会被操作系统阻塞，直到 ReadFile 返回。

微软官方文档原文：

> *If a single thread is blocked on ReadFile, and the same port handle is used by another thread for WriteFile, the WriteFile call will be blocked until the ReadFile call returns.*
>
> — [Serial Communications in Win32](https://learn.microsoft.com/en-us/previous-versions/ff802693(v=msdn.10))

### 为什么打开调试窗口时不受影响

打开调试窗口后，UI 线程频繁调用串口状态查询（GetCommState / ClearCommError 等），这些调用会间接触发 ReadFile 提前返回，客观上"让出"了内核锁，使 WriteFile 得以执行。这掩盖了底层互斥问题，而非真正解决了它。

### 为什么 SwitchToThread() 无效

之前的尝试在 ReadLoop 末尾加了 `SwitchToThread()` 让出时间片。但由于问题出在**内核态锁**而非用户态调度，让出 CPU 时间片无法释放串口的内部互斥体，反而增加了额外的上下文切换开销，使延迟从 630ms 恶化到 814ms。

## 修复方案：Overlapped I/O（重叠 I/O）

使用 `FILE_FLAG_OVERLAPPED` 打开串口，启用异步 I/O 模式。此模式下 ReadFile 和 WriteFile **各自独立**，不再共享内核锁，实现真正的全双工并发读写。

### 改动概览

| 文件 | 改动 |
|---|---|
| `serial_port.h` | 新增 `m_hReadOL`、`m_hWriteOL` 两个事件句柄成员 |
| `serial_port.cpp` / `Connect()` | `CreateFileW` 添加 `FILE_FLAG_OVERLAPPED`；创建读写完成事件 |
| `serial_port.cpp` / `Disconnect()` | 关闭 overlapped 事件句柄 |
| `serial_port.cpp` / `ReadLoop()` | 改用 overlapped ReadFile + WaitForMultipleObjects 等待读完成或停止信号 |
| `serial_port.cpp` / `WriteLoop()` | 改用 overlapped WriteFile + GetOverlappedResult 等待写完成 |
| `serial_port.cpp` / `SwitchBaudrate()` | 验证阶段的直接 I/O 也改为 overlapped 模式 |
| `serial_port.cpp` / `DetectBaudrate()` | 无需改动（使用独立临时句柄，保持同步模式） |

### 关键代码变更

#### 1. 以 Overlapped 模式打开串口

```cpp
// 修复后
m_hPort = CreateFileW(fullPath,
    GENERIC_READ | GENERIC_WRITE, 0, NULL,
    OPEN_EXISTING, FILE_FLAG_OVERLAPPED, NULL);   // ← 异步模式

// 创建读写完成事件
m_hReadOL  = CreateEvent(NULL, TRUE, FALSE, NULL);
m_hWriteOL = CreateEvent(NULL, TRUE, FALSE, NULL);
```

#### 2. ReadLoop — 异步读 + 多对象等待

```cpp
OVERLAPPED ov = {};
ov.hEvent = m_hReadOL;

BOOL ok = ReadFile(m_hPort, readBuf, sizeof(readBuf), &bytesRead, &ov);
if (!ok) {
    if (GetLastError() != ERROR_IO_PENDING) break;

    // 同时等待：数据到达 OR 停止信号
    HANDLE handles[2] = { m_hReadOL, m_hStopEvent };
    DWORD wait = WaitForMultipleObjects(2, handles, FALSE, INFINITE);

    if (wait == WAIT_OBJECT_0 + 1) {   // 停止信号
        CancelIo(m_hPort);
        break;
    }
    // 数据到达，获取结果
    GetOverlappedResult(m_hPort, &ov, &bytesRead, FALSE);
}
```

COMMTIMEOUTS（`ReadTotalTimeoutConstant = 10ms`）在 overlapped 模式下仍然生效，ReadFile 最多等待 10ms 就会完成，不会无限阻塞。

#### 3. WriteLoop — 异步写 + 等待完成

```cpp
OVERLAPPED ov = {};
ov.hEvent = m_hWriteOL;
DWORD written = 0;

BOOL ok = WriteFile(m_hPort, buf, len, &written, &ov);
if (!ok && GetLastError() == ERROR_IO_PENDING)
    GetOverlappedResult(m_hPort, &ov, &written, TRUE);
```

WriteFile 立即返回，不再被 ReadFile 阻塞。`GetOverlappedResult(bWait=TRUE)` 等待实际写入完成（受 `WriteTotalTimeoutConstant = 100ms` 约束）。

## 原理图

```
修复前（非重叠模式）：
┌─────────────┐     内核串口锁     ┌─────────────┐
│  Read 线程   │ ═════════════════▶│  Write 线程  │
│  ReadFile()  │    (互斥阻塞)      │  WriteFile() │ ← 被阻塞！
└─────────────┘                   └─────────────┘

修复后（Overlapped 模式）：
┌─────────────┐                   ┌─────────────┐
│  Read 线程   │                   │  Write 线程  │
│  ReadFile()  │    各自独立的     │  WriteFile() │ ← 立即返回
│  Wait on     │    Overlapped    │  Wait on     │
│  m_hReadOL   │    事件对象       │  m_hWriteOL  │
└─────────────┘                   └─────────────┘
```
