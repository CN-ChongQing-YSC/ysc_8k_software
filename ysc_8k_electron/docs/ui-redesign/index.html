YSC 8K 驱动 · v1.14.0 · Electron + Vue

「键鼠集火」界面优化 · 四套方案

全部改动集中在按钮的表达形式与信息布局上：把「连接 / 断开」从两个长得差不多的低保真小按钮， 变成能一眼看出哪个是主操作、哪个是危险操作、哪个当前可点的控件；把监看区从三个等权重的数字格， 变成有主次、有状态语义的仪表。配色一个像素都没动。

配色锁定为实机截图取值，四套方案共用 palette.css，禁止自造颜色
对照 现状 v1.14.0 优化前长这样 —— 用当前仓库代码的真实取值复刻

现在的问题

  • 两个按钮长得太像。「连接」是实心蓝（26px 高），「断开」是描边红，高度一样、宽度各占一半 —— 主操作和危险操作在视觉权重上只差一个颜色。
  • 按钮高度 26px。鼠标目标偏小，且和左侧 select 下拉框一样高，缺乏「这是可点的操作」的暗示。
  • 禁用态几乎看不见。--border 做底 + --text-dim 做字，对比度极低，用户不确定是「不能点」还是「坏了」。
  • 监看三格等权重。鼠标机、X、Y 三个卡片一样大、数字一样大，「无 / 1 / 0」在视觉上完全同权，看不出哪个是重点。
  • 状态色只出现在文字上。「未连接」灰色小字、「已连接」绿色小字 —— 颜色是唯一的状态载体，色弱用户无法区分。

这套方案不改什么

  • 配色、字体、圆角、面板结构全部保留。
  • 字段顺序保留（端口 → 波特率 → 角色），这是上个提交刚按操作顺序重排的。
  • 没有新增交互概念，用户不需要重新学习。

方案 A 状态块 Status Block 按钮做成「左图标暗区 + 右文字」的整块命中区，连接状态变成卡片顶部的灯带

按钮怎么改

  • 高度 26 → 38px，命中面积翻倍；左端 40px 独立暗区放图标，即使不看文字也能靠图标区分「接入 / 拔出」。
  • 主按钮加抬升投影，hover 时 translateY(-1px) 上浮并发出蓝色辉光 —— 用动效而不是新颜色来表达「这个能点」。
  • 禁用态做成「凹陷」：底色降到 5% 白、去掉所有投影，配合 对比度明显更低的文字，一眼看出是「条件不满足」而非故障。
  • 危险操作克制化：断开默认只是浅红底 + 红描边，只有 hover 才满血红。避免在静态界面里到处是红色警报。

状态怎么改

  • 卡片顶部 3px 灯带：灰 = 未连接，绿 = 已连接（带辉光），琥珀 = 切换中。形状 + 颜色双通道，色弱也能分辨。
  • 端口号做成等宽 chip，带底色和描边。已连接时不必再找，「COM7 @ 4000000」是一个可直接读的对象。
  • 监看数字 20 → 26px 并启用 tabular-nums，变化时数字不跳位；非零值才点亮蓝色辉光，归零自动变暗。
  • 四角刻线：纯 1px 描边装饰，营造仪表质感，零额外颜色。

取舍

  • 最保守、改动最小，直接落在现有 DevicePanel.vue / MonitorPanel.vue 的 scoped style 里。
  • 不改字段顺序、不改交互逻辑，纯视觉层升级。
  • 灯带占 3px 垂直空间，两张卡片共多占 6px，可忽略。

方案 B 分段控件 Segmented 连接 / 断开合成一个二选一分段控件；监看变成大号开关；参数行去掉输入框边框

按钮怎么改

  • 把「连接」和「断开」合并成一个分段控件。这是本方案的核心：断开一个本来就没连上的设备是无意义操作，所以用 disabled 让它在未连接时不可选 —— 从界面结构上就消灭了误点。
  • 选中态用实心填充，未选中态是纯文字。当前处于哪种状态，扫一眼就知道，不需要读文字。
  • 分段控件整体嵌在 3px 内凹的 --bg-input 凹槽里，像物理拨档开关，与面板表面形成明确的层次。
  • 选中「断开」时填充危险红，选中「连接」时填充品牌蓝 —— 同一种控件承载两种语义，比两个不同按钮更省认知。

布局怎么改

  • 参数行去边框化。端口、波特率、角色从「输入框」变成「标签 ← → 值 ⌄」的右对齐行，整行可点。视觉噪音大幅下降，界面从「表单」变成「设置项」。
  • 监看开关放进面板标题栏右侧，用 38×20px 的滑动开关 + 文字状态。「开始监控」这个动作从此有明确的 on/off 语义，而不是一个悬空的文本框按钮。
  • 监看改成仪表盘：X / Y 两个大数字卡并排（30px），鼠标机 / 键盘机状态作为整宽卡片。数字大小直接反映信息主次。
  • 归零自动降级：值为 0 时数字变暗变灰，不占据视觉焦点。0 不该和 1 一样醒目。

取舍

  • 交互概念有变化（按钮 → 分段），用户需要看懂一次，但之后误操作率最低。
  • 分段控件把「不可用」表达为 disabled 选项，必须配 title 说明原因，否则用户会困惑「为什么点不动」。
  • 适合把这套用到整个软件的其它板块，统一成同一套控件语言。

方案 C 金属层叠 Tactile 按钮做成有厚度、会下沉的实体按键；连接状态变成呼吸的环形灯

按钮怎么改

  • 用光影而不是颜色做「高端感」。主按钮叠了四层：顶部 1px 白色内高光、底部 2px 暗内阴影、外投影、hover 辉光。这是实体按键的物理特征，配色一个没加。
  • 按下时真的会下沉。translateY(2px) + 内阴影加深，90ms 极短过渡 —— 手感来自位移，不来自变色。
  • 危险键默认极度克制：一层几乎看不见的红底 + 红描边。只有鼠标悬停时才整颗变红。静态界面里不再有刺眼的红色警报。
  • 留了 .ghost 第三档实体键，用于「刷新」这类次要动作用同样的物理语言，三种权重同源。

状态怎么改

  • 环形状态灯替代文字状态：外圈 30px 环 + 内芯圆点。未连接 = 灰环 50% 透明；已连接 = 绿环 + 辉光 + 内芯呼吸；切换中 = 琥珀环 + 内芯旋转。
  • 三重冗余：环的形状（有/无辉光）、颜色、旁边的文字副标题，任何一种通道都能独立表达状态。
  • 端口信息竖排右下角，等宽字体，端口号和波特率分行 —— 已连接时它是最重要的信息，给它独立的位置。
  • 监看用「表盘」：径向渐变做钟表玻璃的反光，数字 28px + 蓝色辉光。三个表盘，有值的亮、无值的暗。

取舍

  • 视觉最「贵」，与截图现有配色结合后整体质感提升最明显。
  • 多层阴影 + 辉光在低端集显上略费一点 GPU，但都是 box-shadow/transform，可走合成层，实测无压力。
  • 动画仅用 transform + opacity，且全部 < 220ms，符合 400ms 反馈阈值。
  • 需要同时提供 prefers-reduced-motion 降级分支。

方案 D 控制台 Console 两台设备收进标签页，参数改成等宽表格，按钮做成左对齐的命令条

布局怎么改

  • 两台设备改成标签页。集火场景下用户绝大多数时间只关心其中一台（正在出问题的那台）。标签页让每次只看一台，另一台的连接状态由标签上的小圆点持续告知 —— 不丢失全局感知。
  • 垂直空间立刻省下一半，腾出来的位置可以放设备详情或日志，也为以后加第三台设备留了余地。
  • 参数改成等宽表格：左列 PORT / BAUD / ROLE 大写小字号，右列右对齐等宽值。所有值的起始位置在垂直方向严格对齐，扫读一列值比扫读一堆输入框快得多。

按钮怎么改

  • 命令条形态：33px 高，左对齐（不是居中的胶囊），左边缘一条 2px 强调色的「命令脊」，右侧带快捷键角标。
  • 左对齐 + 图标让按钮读起来像一条可执行的指令，而不是一个装饰块 —— 与整个界面的工程工具气质一致。
  • 快捷键角标是真实功能：Enter 连接、Esc 断开。集火调试时高频切换，键盘操作省掉精确瞄准小按钮的动作。
  • 禁用态保留命令条的骨架（脊和角标还在），只降低整体对比度 —— 用户仍能看出「这里有个连接命令」，只是现在执行不了。

监看怎么改

  • 日志式读数：每行「键 ← → 值」，等宽右对齐，值域用 tabular-nums。数字变化时不会左右抖动。
  • X / Y 用 26px 大字单独成行，其余信息小字，主次分明。
  • 状态行用 ● + 等宽文字，与命令行提示符同构。
  • 这套排版天生适合「截图发群里排查」，信息密度高且对齐整齐。
